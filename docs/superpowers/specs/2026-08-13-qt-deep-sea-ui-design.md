# KY-DIMM 深海科技仪器风 UI 设计

## 目标

在不改变相机采集、测量算法、线程通信和数据格式的前提下，优化 KY-DIMM 主界面与设置对话框的视觉层级，使它同时适合长时间实时观测和现场诊断。

## 设计方向

采用“实时观测优先、诊断信息常驻”的双层仪器控制台。主视区持续突出全画幅和双星质心结果；ROI、AOI、丢帧、日志等诊断内容保持可见，但通过分组、弱化颜色和紧凑状态卡降低干扰。

目标平台是 Windows Qt Widgets 桌面应用，基准窗口为 1280×800，主要输入方式为鼠标和键盘，主要语言为简体中文。

## 主界面

### 顶部操作区

顶部拆分为左侧身份与状态、右侧操作两组：

- 左侧显示 KY-DIMM 标题、相机状态、采集状态和实时测量率。
- 右侧显示连接、断开、设置、开始采集、停止采集。
- 开始采集使用绿色实心按钮，停止采集使用珊瑚红实心按钮；其他按钮使用深色描边样式。
- 状态必须同时使用文字、颜色和边框/徽标表达，不依赖颜色单独传达状态。

### 中央观测区

中央区域保持水平分栏：左侧约 58% 为全画幅观测区，右侧约 42% 为结果与诊断区。

全画幅观测区：

- 使用接近黑色的成像底色，避免面板色干扰星点对比度。
- 增加标题栏，显示“全画幅观测”和当前图像尺寸。
- 使用青色细边框作为观测边界，不加入重阴影和装饰性动画。
- 图像未就绪时显示明确的空状态文本。

右侧结果区按以下顺序排列：

1. `r0 / seeing / theta0 / tau0` 四项结果卡片；数字最大，单位和标签次级显示。
2. StarA / StarB 两张 ROI 卡片；卡片中同时显示图像、坐标和定位状态。
3. 测量状态、有效样本进度和窗口进度条。

### 底部诊断区

底部拆分为日志和状态卡：

- 左侧为深色终端式日志区域，使用等宽字体，保持自动滚动。
- 右侧用紧凑的两列状态项展示 ROI 跟踪、AOI、相机丢帧、队列丢帧和最后错误。
- 最后错误使用错误颜色、错误标题和具体文本；无错误时显示中性的“无错误”。
- 诊断信息不覆盖主观测区，也不改变原有日志和状态更新逻辑。

## 设置对话框

保留现有五个标签页：物理/光学参数、采集设置、图像处理参数、触发设置、数据存储。仅调整视觉层级和控件样式：

- 标签页使用深色面板和清晰的选中态边框。
- 每个参数分组使用统一卡片边框、标题色和内部间距。
- 输入控件统一高度、边框、焦点态和禁用态；不改变控件类型及已有校验范围。
- 图像处理参数组突出 Otsu、连通域、面积和小核参数，并保留算法摘要说明。
- 对话框底部按钮明确区分取消和确认，确认按钮使用主强调色。
- 保持现有键盘 Tab 顺序和滚轮修改数值的交互；焦点状态使用高对比度青色边框。

## 实现边界

主要修改范围：

- `src/UiTheme.cpp`：统一颜色令牌、字体、按钮、面板、标签页、输入控件、焦点态和状态样式。
- `src/MainWindow.cpp`：调整运行时布局、分组标题、状态卡和观测区结构；不修改 worker 调用、信号连接和测量逻辑。
- `src/SettingsDialog.ui`：补充或调整布局层级、分组标题和控件默认视觉属性；不修改参数名称和数据绑定。
- `src/SettingsDialog.cpp`：仅在布局重组需要时调整分组和控件排列，不改变配置读写语义。

不新增图片资源、字体资源、第三方依赖或动画框架。优先使用 Qt Widgets、QSS 和现有动态布局。

## 可访问性与响应式约束

- 所有主要文字与背景保持可读对比度。
- 所有可操作控件保留键盘访问和可见焦点态。
- 中文文本容器不得通过固定宽度造成明显截断。
- 1280×800 为首要验证尺寸；窗口缩小时，日志和次级诊断内容优先压缩，主观测区和结果区保持可用。
- 状态颜色必须配合文字或边框形状，不单独依赖颜色。

## 验证方案

- 使用现有 Python 源码契约测试，确认控件对象名、中文文案和算法配置绑定未被破坏。
- 使用 Qt `uic` 检查 `src/SettingsDialog.ui` 可生成。
- 使用 VS18/CMake 交接文档流程构建 Release；若环境再次卡在 SDK 探测，沿用已验证的自动 MOC/UIC、串行编译、链接和部署检查路径。
- 检查 1280×800 下主界面的四个区域：顶部操作区、中央观测区、结果/ROI 区、底部诊断区。
- 检查设置对话框的标签页、输入焦点、按钮状态和中文文本是否完整。
