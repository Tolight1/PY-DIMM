# 相机采集率与有效测量率分离设计

## 背景

当前界面只显示测量线程根据有效双星样本时间戳计算的速率。相机线程已有统计信号，但相机统计中的速率字段没有实际计算，导致无法区分“相机送入程序的帧率”和“有效双星样本处理率”。同时，参数计算把有效测量率低于配置值作为硬性无效条件，因此有效样本达到窗口后仍可能显示 `--`。

## 已批准目标

1. 同时显示相机采集率和有效测量率。
2. 相机采集率反映相机成功回调并送入程序的帧率；有效测量率继续反映两个星点均识别成功并进入计算的样本率。
3. 参数计算在有效样本数达到 `r0WindowFrames` 后发布结果，不再因测量率低于配置值而返回无效。
4. 有效样本不足时继续显示等待状态；`tau0` 本身的样本数和分辨率判断保持不变。

## 设计

### 速率数据流

- `CameraStatistics` 增加明确命名的 `acquisitionRateHz` 字段。
- Pylon 成功抓帧回调使用单调时钟时间戳维护最近 100 个成功帧，并计算相机采集率。
- `MeasurementWorker` 保留现有 `currentRateHz()` 逻辑，继续计算有效测量率。
- 两个速率分别通过现有相机统计信号和测量统计信号传到 GUI。
- 诊断 CSV 将相机统计列命名为 `acquisition_rate_hz`，避免与参数结果中的 `measured_rate_hz` 混淆。

### 界面

- 顶部状态栏新增 `相机采集率：-- Hz`。
- 现有 `实际测量率` 改为 `有效测量率`。
- 相机采集率按相机成功回调速率显示；有效测量率仍按有效双星样本速率显示。
- 停止采集或断开相机时两个速率都恢复为 `-- Hz`。
- 有效测量率颜色只用于提示速率状态，不再决定参数是否可以显示。

### 参数计算门禁

`AtmosphereCalculator::calculate()` 的有效性顺序调整为：

1. 记录实际有效测量率到结果元数据；
2. 有效样本数不足 `r0WindowFrames` 时返回等待状态；
3. 样本数达到窗口后执行现有方差、`r0`、`seeing`、`theta0` 和 `tau0` 计算。

配置中的 `measurementRateHz` 仍可用于相机连续采集目标速率和结果更新节拍，但不再作为参数结果的硬性有效门禁。

## 验收标准

- 相机运行时顶部同时出现相机采集率和有效测量率，且两者来自不同统计路径。
- 在有效测量率约 43.8 Hz、有效样本数达到 1000/1000 时，四个主参数不再因帧率原因显示 `--`。
- 有效样本数小于窗口时，结果仍为无效并显示等待样本状态。
- `tau0` 无法由当前历史样本分辨时仍按现有规则显示 `--` 或分辨率提示。
- 现有 Python 契约测试、Release 构建和工作区已有修改均不被破坏。

## 范围边界

本次不改变相机 AOI 几何、星点识别算法、有效样本判定规则、采样数据物理含义或 GitHub 发布流程；不承诺当前相机能够达到 100 Hz，只负责如实分离并显示两个速率，并取消参数计算对该速率的硬性拦截。
